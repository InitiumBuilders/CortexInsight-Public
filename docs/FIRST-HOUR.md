# The first hour

A new operator's first session, told as it happens. Everything below is what the fresh-vault harness (`npm run fresh`) sees when it starts from nothing: an empty vault, no passphrase, no fleet tree. Where the story goes past what the harness can see, it says so.

## Minute zero: the gate

The window opens dark, with one field and a line under it: a living window into the SEMBLE CORTEX. The field asks for a passphrase and a second field asks for it again. Twelve characters or more. Nothing in the code can open this gate; the hash of what you type is the only key, and it lives in your vault.

You type it twice. The vault pairs itself to this machine as it saves. If someone copies the vault to another computer later, that computer will see a decoy and this one will get a record of the attempt.

The harness saw: the gate in setup mode, the hash stored, the device trusted. No errors.

## Minute one: Pulse, with nothing behind it

Pulse opens. The attention list at the top ranks what is wrong, and the first item is the one that matters:

> FIRST RUN. No fleet tree is set. The console reads a fleet tree in WSL: a home folder holding `logs/interactions` and `agents`. Set the fleet path on Config → Preferences, then reopen Pulse.

Under it, the readings are honest about their emptiness. No Motus is set. Nothing is on fire. The rhythm ring is dark because there have been no turns. The reading itself is short, because there is nothing to read yet.

If you already have a fleet tree in a WSL home, the console found it before you got here, and this card never appears. The harness hides the tree on purpose, so the card had to earn its place.

## Minute three: the path

Config → Preferences. The Fleet path field takes the UNC path to the tree, something like `\\wsl.localhost\<distro>\home\<you>\<your-tree>`. Save it and go back to Pulse. The card is gone. The constellation shows your seats, dormant, with no turns on record. The relay line now says whether the loopback proxy answers.

## Minute five: the first word

Command. Type `/help`. The reply lists every command, the agent tool, and the links to these pages, and it costs no turn. Now type a sentence to Davara. The reply arrives with its latency. On Secure, the sent log has a provenance stamp: this command came from this machine.

Type `/reading`. With one turn on record the sentence is still thin; by the end of the day it will have a rhythm to describe.

## Minute ten: the bridge

Model. The bridge panel says the runner does not yet carry the guarded block. Install. One block goes into the runner after the tools line, backed up with a timestamp, checked with `bash -n`, rolled back if that fails. From this turn on, every seat's model, effort and turn budget are read fresh each turn, and the brief is prepended to every message.

This is the moment the console stops being a window and becomes part of the loop.

## Minute fifteen: the agent learns to talk back

Send one message: read `~/.cortexinsight/README-FOR-AGENTS.md` and remember it. The manual is rewritten every boot. From now on the agent can add a task to your board, mark it doing and done, claim it, ask you a question, hand work to another seat, bank a learning, leave a note, or ask the studio for an image. Every one of those is a line appended to a queue that the console validates and applies under your caps.

Ask it to add a task. Go to the Board. There it is, tagged with the agent's name.

## Minute twenty: the board starts to move

Add three tasks of your own with the grammar in the title: `!! First public build @davaris #console`. The WIP strip counts. Assign one to a seat and press Run. Watch it on Live: the transcript streams, tool calls and file edits as they happen, with a NOW card on Pulse showing the exact ask and the elapsed time.

When it reports done, the console checks: turns since the task was created, files written, word overlap between the title and the work. The verdict lands on the card as strong, partial or thin.

## Minute thirty: a loop

Duo-Drive. Turn on one seed loop, Polish Pass, with a cadence and a project. Register the project first: name, URL, local folder, repo, and a line of ethos. The loop will read the creed, the systems sight, its organs, your ethos and the reading before it touches anything, and it will report in the contract: a title, a confidence with its basis, a falsifier with a clock, one lived turn walked, what it did, which files, and the next move.

The first pass may skip. A skipped pass that says why is a good pass.

## Minute forty: the hands

Motus Max. Read the scope and the pacing. Add the windows you allow. Hold the arm switch. The strip says READING, then READY, with a lever and a first step chosen from the strategic read. Press Drive, or leave it, and the arm expires on its own.

If you drive: the HUD appears over every display, the audit line ticks per cycle, and the panic key is one press away. Most real work is files, commands and APIs; the screen is the instrument only when the screen is the work.

The harness stops before this point. It arms nothing and spends no turn.

## Minute fifty: the close

Back to the Board. Nothing is stale yet, so the sweep is quiet. THE CLOSE proposes what the ledger can already see: a claimed done, a long wait, the oldest priority. Today it may propose nothing. In a week it will propose three.

## Minute sixty: the reading, again

Pulse. The ring has a shape now. The sentence names your window, your stocks, and the attractor your board is falling toward. The same sentence is at the top of the brief every agent reads on its next turn. What you did in this hour changed what the fleet is told next. That is the loop, closed once.

## What the harness proves, and what it cannot

It proves a fresh vault can set a passphrase and pair, that every room renders without a fleet tree and without errors, and that Pulse tells a new operator the way in. It cannot prove the relay, the bridge, a drive, or a loop on a machine that is not the authors'. That first run on a foreign machine is the falsifier in `FUTURE.md`, and it is still open.
